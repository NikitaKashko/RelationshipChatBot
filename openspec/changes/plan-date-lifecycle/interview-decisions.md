# Proposal

История опроса. Это архив последовательных решений; актуальные контракты находятся в specs/, последующие уточнения ниже имеют приоритет. Код остаётся прототипом.

## Why

Пара должна не только собирать места, но и планировать свидания, учитывать состоявшиеся и отменённые походы и избегать нежелательных повторов. Перед реализацией и выбором VPS нужно определить правила состояний, отзывов, рекомендаций и напоминаний.

## What Changes

Подтверждено пользователем:
- Первая версия только для пары владельца, с возможностью расширения на другие пары позже.
- Интерфейс: карточки в обычном Telegram-боте; адрес, ссылка на карту и фото при наличии.
- Личный город запрашивается при первом входе пользователя.
- Город пары задаётся отдельно: один партнёр предлагает, второй подтверждает.
- ИИ должен учитывать локальную коллекцию в базе. Пользователь предложил MCP; способ доступа к данным пока не выбран.
- Запросы к ИИ вводятся обычным текстом, без обязательных команд. ИИ сам обращается к коллекции и подбирает варианты под запрос; технический способ доступа пока не утверждён.
- Поиск и планирование по умолчанию используют подтверждённый город пары; временно можно выбрать другой город без изменения профилей. Пока город пары не подтверждён, город поиска запрашивается явно.
- Основная карта в карточках — Яндекс Карты.
- По умолчанию ИИ подбирает только из коллекции. Интернет-поиск запускается лишь по явной просьбе пользователя.
- ИИ коротко уточняет только недостающие важные детали запроса; известные город и предпочтения повторно не запрашивает.
- Список идей общий для пары; видно, кто добавил каждое место.
- Отдельно существует список для ближайшего свидания, отделённый от общей копилки идей.
- Оба партнёра могут редактировать список кандидатов ближайшего свидания. Подборка ИИ добавляется только по кнопке пользователя.
- Кандидаты и итоговый план разделены: добавление в кандидаты не означает обязательное посещение.
- Любой партнёр может сохранить или изменить итоговый план без подтверждения второго.
- Уведомление об изменении плана отправляется одним сообщением при сохранении; изменения списка кандидатов не уведомляют партнёра.
- Любой партнёр отмечает фактическое посещение для пары; впечатления каждый сообщает отдельно. Посещение не выводится автоматически из прошедшей даты.
- Если в место не пошли, оно остаётся доступным в копилке. Фриз или исключение из рекомендаций задаются отдельным действием; перенос сохраняет план с новой датой.
- Опрос отправляется обоим на следующий день в 12:00 по часовому поясу пары, без повторов при молчании. Время можно изменить в настройках. Если один уже отметил посещение, второй сообщает только впечатления.
- Индивидуальный отзыв: «Понравилось / Нейтрально / Не понравилось» и «Хочу ещё / Не скоро / Больше не хочу», необязательный комментарий. Свободный текст ИИ переводит в оценки только после подтверждения пользователем.
- После подтверждённого посещения место автоматически замораживается на 30 дней от даты посещения. Срок можно изменить, фриз снять. По ответу «Хочу ещё» бот предлагает сократить срок, а не меняет его молча.
- Фриз исключает место из автоматических рекомендаций, но не мешает ручному добавлению в план. «Больше не хочу» хранится как отдельное предпочтение пользователя.
- «Больше не хочу» от любого партнёра исключает место из автоматического подбора для пары; карточка остаётся, ручной выбор разрешён с пометкой предпочтения партнёра. Пользователь может изменить свой отказ.
- Любой партнёр может изменить или снять общий фриз; второй получает одно уведомление. Личный отказ другого этим не изменяется.
- Фильтры копилки: «Все / Добавил я / Добавил партнёр / Нравится обоим / Во фризе / Были». Оценки интереса добровольные: «Хочу сходить / Не интересно».
- ИИ может выбирать неоценённые места, явно отмечая неизвестный интерес партнёра; взаимные совпадения имеют приоритет. Неоценённое место не считается отказом или совпадением.
- Ручное добавление: ссылка на карты или обычный текст → определение места → проверка карточки пользователем → сохранение по кнопке. При нехватке данных бот уточняет; собственные идеи без адреса разрешены.
- Обязательные поля карточки: название, категория и автор. Адрес, ссылка на карту, описание, бюджетный ориентир и фото добавляются при наличии. Для найденных сведений сохраняются источник и дата проверки; неизвестные цена и часы не выдумываются. Бюджет помечается как стоимость на человека или на двоих.
- Дубли проверяются по ссылке либо названию и адресу: бот предлагает существующую карточку, сохраняет первоначального автора и позволяет второму выразить интерес. Разные филиалы считаются разными местами.
- Категории: стартовые и собственные категории пары; одному месту можно назначить несколько.
- Явный интернет-поиск выдаёт 3–5 карточек с объяснением соответствия запросу, источником и кнопками «В идеи / В кандидаты свидания / Ещё варианты». Автоматического сохранения нет; добавление в кандидаты одновременно сохраняет место в копилке.
- Фото: одна обложка и до двух дополнительных по кнопке, если источник разрешает использование; пользователи могут загружать свои фото. Без фото используется текстовая карточка. Случайные изображения не выдаются за подтверждённые фото места.
- При неполных данных показываются источник и неизвестные поля; разрешено сохранить непроверенную идею с исходной ссылкой. При сбое поиска можно повторить запрос. ИИ не выдумывает заведения или подтверждение сведений.
- Итоговый план требует дату, примерное начало и конец; идеи и кандидаты не требуют расписания. ИИ понимает относительные даты, но перед сохранением показывает точные дату и время для проверки.
- У пары один общий список кандидатов ближайшего свидания, несколько сохранённых планов на разные даты и история прошедших. План содержит одно или несколько мест с редактируемым порядком.
- При отсутствии подходящих мест бот объясняет причину и предлагает «Изменить условия / Посмотреть замороженные вручную / Найти новые». Интернет запускается только по явной просьбе, ручной выбор не снимает фриз.
- Оба партнёра редактируют общие карточки, автор добавления сохраняется. Вместо удаления используется архив; восстановить может любой. Личные оценки и отзывы изменяет только их автор.
- При сохранении плана проверяется версия: конфликт с изменениями партнёра показывается пользователю, чужие правки не затираются молча.
- При завершении пары взаимный доступ немедленно закрывается, будущие уведомления отменяются. Каждому остаётся личный архив собственных идей и отзывов; общие планы и чужие отзывы не переносятся к новому партнёру.
- У каждого свои тихие часы, по умолчанию 23:00–09:00 в личном часовом поясе. Все исходящие уведомления, включая знаки внимания, откладываются до окончания тихих часов; изменения одного плана объединяются. Опрос планируется по часовому поясу пары.
- Кнопки внимания: «Хочу внимания», «Думаю о тебе», «Хочу обнять». Для каждой нужны несколько вариантов текста уведомления.
- Два типа ссылок: приглашение доступа к боту от владельца и приглашение в пару от зарегистрированного пользователя. Получатель подтверждает создание пары; код дружбы остаётся запасным способом. Приглашение в пару позволяет новому партнёру зарегистрироваться.
- Ссылки одноразовые, действуют 7 дней, могут быть отменены и перевыпущены. Приглашение в пару недействительно, если отправитель уже создал другую пару.
- Отправитель задаёт своё имя для уведомлений, получатель может переопределить обращение к партнёру; обращение получателя имеет приоритет.
- Для каждой кнопки внимания заранее готовятся 5–7 фраз, случайный выбор без повтора предыдущей. Одно нажатие отправляет текст автоматически, без ввода текста, подтверждения или запроса DeepSeek. Только нажатие инициирует знак внимания; автоматических знаков нет. Общий предел — один знак в минуту на отправителя, с учётом тихих часов получателя.
- Уточнение 2026-10-16: «Хочу внимания» полностью заменено на «Хочу поцеловать» с шестью заранее подготовленными фразами. «Думаю о тебе» и «Хочу обнять» остаются без изменений.
- У каждого необязательный профиль: интересы, нежелательные активности, ограничения по еде и доступности, привычный транспорт. ИИ учитывает предпочтения обоих и условия текущего запроса; геолокация не обязательна, незаданный бюджет не уточняется обязательно; время требуется для сохранённого плана.
- Диалог с ИИ личный, сохраняет контекст для уточняющих сообщений. Партнёр видит общие карточки и сохранённые планы, но не личную переписку. Устойчивые предпочтения из разговора записываются только после подтверждения; предусмотрена кнопка «Новый разговор».
- Одно отключаемое напоминание за 2 часа до начала свидания, с учётом тихих часов. Отмена или перенос уведомляет партнёра и отменяет либо перепланирует напоминание и последующий опрос.
- Передача DeepSeek после согласия обоих: необходимые поля мест, даты плана и разрешённые предпочтения; переписка — только автора текущего диалога. Telegram ID, имя для уведомлений и фотографии не передаются. Личные заметки и тексты отзывов используются только по отдельному разрешению; оценки и фриз учитываются без полного текста.
- Сейчас не включать квоты и ограничения количества ИИ-запросов; сохранить возможность настройки ограничений в будущем. Это решение относится к ИИ и поиску, минутное ограничение кнопок внимания остаётся.
- Уточнено: 500 ₽/месяц — ориентир расходов ИИ и поиска, с учётом расхода и уведомлением владельцу при достижении суммы, без остановки запросов. VPS оплачивается отдельно.
- Личная переписка ИИ хранится 30 дней; доступны очистка истории и новый разговор. Подтверждённые предпочтения, места, планы и отзывы хранятся отдельно и очисткой переписки не удаляются.
- Ежедневные копии базы: 7 дневных и 4 недельных, только на том же VPS; внешних копий и внешнего хранилища не требуется. При потере VPS локальные бэкапы также теряются. Пользовательские фото сохраняются через Telegram file_id, без собственного фотохранилища.
- Очередь уведомлений сохраняется в базе. После сбоя опрос догоняется не позднее 48 часов от назначенного времени; напоминание — только до начала свидания; знаки внимания старше 12 часов не отправляются. Тихие часы соблюдаются при восстановлении.
- Ошибки DeepSeek и поиска: короткое сообщение и кнопка «Повторить», запрос и черновик сохраняются; автоматических повторов платного запроса нет. Ручные функции продолжают работать.
- Панель владельца: отдельная веб-страница на том же VPS, доступ через SSH-туннель; публичный веб-доступ и домен не нужны.
- Показатели панели: состояние бота и последнего бэкапа, расходы DeepSeek и поиска по дням, запросы и ошибки, очередь уведомлений, числа пользователей, пар, идей и свиданий. Личные диалоги и тексты отзывов не показываются.
- Действия панели: создание/отмена приглашений доступа и ручной запуск бэкапа с результатом. API-ключи не отображаются, будущие лимиты выключены.
- Сохранить объединение пары по коду, знаки внимания, категории и общую коллекцию мест.
- Позволить запрашивать у ИИ план свидания.
- DeepSeek API обязателен; через интерфейс ИИ пользователь должен искать новые места в интернете и добавлять найденные места в коллекцию.
- Опрос должен охватывать весь продукт. Для каждого вопроса нужны рекомендованный вариант с обоснованием и альтернативы.
- Предусмотреть фриз места: оно исключается из автоматических рекомендаций, но остаётся доступным для ручного выбора.
- Сначала согласовать и задокументировать требования, затем оценить ресурсы. Пользователь заказывает VPS, после этого выполняется развёртывание.

- Начатое приглашение закрепляется за Telegram-аккаунтом; регистрацию можно продолжить позже, другому аккаунту ссылка недоступна. До пары можно сохранять личные идеи, после объединения они переходят в общую копилку.
- Опрос назначается на 12:00 следующего календарного дня после окончания свидания, включая окончание после полуночи. Общий часовой пояс предлагается и подтверждается вместе с городом пары. Изменение пояса пересчитывает будущие уведомления, но не меняет фактический момент сохранённых планов.
- Каждый поход имеет отдельную запись посещения и отдельные отзывы. Новый поход обновляет автоматический фриз от новой даты. Любой исправляет факт посещения с уведомлением второго; фриз пересчитывается по последнему действительному посещению. Ручные изменения фриза хранятся отдельно и не отменяются молча исправлением истории.
- Прошлые и спонтанные посещения добавляются вручную через «Уже были», с точной или приблизительной датой, отзывами и выбором необходимости фриза. Автоматический опрос для вручную добавленных посещений не отправляется.
- Текстовая просьба к ИИ изменить план создаёт изменённый черновик; сохранение и уведомление партнёру выполняются только после нажатия «Сохранить» пользователем.
- Источник интернет-поиска выбирается после сравнения API по качеству в России, ссылкам на Яндекс Карты, условиям использования фото и цене. Карта в карточке не определяет поставщика поиска. Значительно более дорогой каталог требует согласования перед подключением; 500 ₽ остаются ориентиром.
- Основной способ взаимодействия — управление через ИИ обычными сообщениями; меню и ручные изменения сохраняются как второй по приоритету способ. Правила подтверждения записи изменений остаются действующими.
- Явно заданные ограничения запроса обязательны; незаданные ограничения не навязываются. Можно добавлять и изменять условия последующими сообщениями, если подборка не понравилась, сохраняя контекст. Бот не обязан спрашивать бюджет, если пользователь не сделал его условием; уточняются только необходимые для действия данные.
- Пользователь предложил распознавание голосовых сообщений. Голосовые включены в план релиза; локальные tiny/base проверяются до выбора размещения, правила передачи и хранения определены далее.
- Голосовой запрос обычно обрабатывается сразу после распознавания; при сомнительной расшифровке бот уточняет. Это не отменяет подтверждение записи изменений кнопкой и отдельное подтверждение удаления аккаунта.
- Аудио хранится только во временном файле до завершения распознавания и затем удаляется; в истории сохраняется текст на 30 дней. Если используется внешний API, согласие на передачу аудио запрашивается до первого использования.
- Пользователь предпочитает локальное распознавание при условии небольших ресурсов VPS; окончательный способ выбирается после оценки памяти, скорости и качества русского.
- У пользователя уже есть VPS: KVM SSD Start, 1 CPU / 768 МБ RAM / 7 ГБ SSD, vm6 EU1; увеличить RAM и CPU на нём нельзя. Пользователь допускает покупку второго VPS для распознавания. Сервер пустой, установлен Debian 13; базовая защита проверена, распределение ASR выбирается измерениями. Заказ дополнительного сервера не выполнен и пока не требуется.
- Уточнено: существующий VPS полностью пустой, других сервисов нет. Выбран и установлен Debian 13; серверные записи хранятся вне репозитория.
- Выгрузка личных данных и удаление аккаунта с подтверждением: пара завершается, личная переписка, предпочтения и отзывы удаляются; партнёру остаются его данные, общие карточки обезличиваются. Резервные копии очищаются по ротации до 4 недель, восстановление повторно применяет удаления.
- Первый полноценный релиз содержит все согласованные функции, с проверкой по этапам: регистрация/коллекция → планы/отзывы → ИИ/поиск → панель/эксплуатация. Сравнение поисковых API выполняется до заказа VPS.

## Capabilities

### New Capabilities

OpenSpec-спецификаций ещё нет; существующие функции прототипа также предстоит описать.

- `pair-management`: коды, подтверждение пары, разрыв, сохранение или удаление личных данных.
- `affection-notifications`: знаки внимания, доставка, частота, настройки уведомлений.
- `shared-places`: категории, предпочтения, повторные посещения, фриз, архив, ручной выбор.
- `date-planning`: запросы ИИ, кандидаты, сохранение планов и уведомление партнёра, перенос, отмена и факт посещения.
- `date-feedback`: индивидуальные отзывы, повторное посещение и влияние ответов на рекомендации.
- `scheduled-notifications`: опрос после свидания, часовой пояс, тихие часы, повторные попытки.
- `ai-assistance`: границы ИИ, передаваемые данные, лимиты расходов, поведение при недоступности.

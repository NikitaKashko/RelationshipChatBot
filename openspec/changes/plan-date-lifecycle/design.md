## Уточнение выпуска 2026-10-12

Текущий прототип: только приглашения ссылками, Go-бот, DeepSeek, панель и бэкапы. Разрыв пары, экспорт/удаление, расширенные настройки уведомлений и бюджет — следующие итерации. Удаление аккаунта пока недоступно; restore проверяет integrity/foreign keys и отклоняет базы с непустым deletion ledger до реализации независимого replay. Ниже сохранены также проектные решения будущих этапов.

# Design

## Context

См. proposal.md и девять контрактов в specs/. Прототип — aiogram, httpx и SQLite с таблицами users/requests/places/likes/cooldowns. Он хранит FSM в памяти, удаляет общие места при разрыве, не поддерживает расписание и сохраняет одну категорию. Эти правила нельзя переносить в новый релиз как готовое поведение.

Первый релиз обслуживает одну пару с возможностью расширения. Номинальная память существующего сервера меньше 1 ГБ; тяжёлые серверные зависимости не подходят. 2026-10-12 пользователь изменил выпуск: развернуть прототип сейчас; бюджет и голос отложены, остальные незавершённые функции остаются последующим развитием.

## Goals / Non-Goals

**Goals:** общие сервисы действий для ИИ и кнопок, изоляция по пользователю/паре, атомарное сохранение с очередью, миграции, восстанавливаемые данные, измеряемая нагрузка.

**Non-Goals:** публичный веб-интерфейс пользователей, сервер локальной LLM, бронирования/покупки, постоянное хранение аудио и собственное фотохранилище.

## Decisions

### Lightweight application

По решению пользователя ядро первого релиза реализовать на Go: Telegram long polling, доменные сервисы, DeepSeek HTTP API, фоновые задания и SQLite WAL. Сетевые вызовы имеют context, timeout и cancellation; транзакции не охватывают сеть. Развёртывание — собранный бинарный файл и systemd без Docker, Redis и PostgreSQL на старте. Конкретную Telegram-библиотеку и SQLite-драйвер выбрать при подготовке Go-каркаса; проверить сборку для Debian VPS и переносимость миграций.

Whisper.cpp tiny остаётся отдельным CPU-процессом с очередью и ограничением ресурсов. Go не заменяет распознавание или внешний DeepSeek. Ожидаемая экономия ядра должна подтверждаться измерениями RSS и нагрузки; дешевизна масштабирования не гарантируется одним выбором языка.

Выбрана встроенная лёгкая Go-панель: серверный HTML/CSS, графики usage и действия приглашений/бэкапа, без Grafana. Один бинарный файл запускается как бот и панель под отдельными non-login пользователями; общая SQLite-группа допускает необходимые записи. Loopback 127.0.0.1:8080, SSH-туннель, пароль, сессия и CSRF обязательны. Денежные графики отложены.

Python-код остаётся историческим прототипом и тестовыми примерами поведения; не продолжать его как production-ядро. SQL-схему и сценарии тестов переиспользовать после проверки, а авторизованные сервисы и обработчики перенести на Go. Python не является зависимостью production-бота.

Альтернативы: PostgreSQL полезен при росте конкурентной записи, но добавляет память и эксплуатацию; Redis не нужен для долговечной очереди двух пользователей. SQLite-соединения короткие, записи транзакционные, сетевые запросы выполняются вне транзакций.

### Data model and ownership

| Сущности | Содержание и ограничения |
|---|---|
| users, profiles, consents | Telegram identity, города/часовые пояса, имена, тихие часы, личные предпочтения, версии согласия |
| invitations, pair_members, pairs | хеши случайных токенов, тип/expiry/claim/revocation, максимум одна активная пара на пользователя, согласованная локация |
| places, categories, place_categories | автор, личный или парный scope, источники полей, verification, архив, версия |
| place_preferences | личный интерес и независимый отказ, авторская запись |
| candidates, plans, plan_items | общий список, несколько планов, UTC-начала/окончания, исходный timezone, порядок, version, snapshot карточки |
| visits, visit_items, reviews | точность даты, факт/исправление, отдельные личные отзывы каждого похода |
| freeze_overrides | ручное until/снятие и время применения; автоматический deadline вычисляется из действительных посещений |
| conversations, messages, drafts | личный контекст, expiry 30 дней, подтверждаемый action payload, target version, actor/pair scope |
| notifications, api_usage, backup_runs | очередь, relevance/expiry, delivery outcome, provider usage/cost uncertainty, результат копирования |
| deletion_ledger | минимальные неприватные маркеры удалений для повторного применения при восстановлении |

Все общие действия разрешаются только активным членам указанной пары, личные тексты — автору. ИИ никогда не передаёт pair_id или actor_id как доверенный аргумент: их подставляет сервер. Регистрация и создание пары используют только invitation deep links; код дружбы исключён из интерфейса.

При разрыве собственные добавления и отзывы проецируются в личный архив; ссылки на чужие тексты и общие планы не переносятся. При новой паре перенос собственных идей не восстанавливает прежние общие связи. При удалении владельца карточка, остающаяся в общей истории партнёра, обезличивается.

### Shared action layer and AI tools

Ввести ограниченные инструменты чтения коллекции/предпочтений/посещений и подготовки действий. Они работают внутри приложения: отдельный MCP-сервер не нужен для свободного текста и чтения SQLite. MCP можно добавить позже над теми же сервисами, если появится внешний клиент. Это технический выбор, а не ограничение разговорного интерфейса.

DeepSeek выбирает инструменты; сервер проверяет аргументы, разрешения и согласие, фильтрует запрещённые места ДО ранжирования. Модель не получает произвольный SQL, shell или сеть. Область допустимых записей определяется сервером, не текстом модели. Черновики сохраняются с автором, pair generation и исходной версией. Кнопка выполняет сравнение версий и атомарную запись; повторный callback идемпотентен. Завершение пары/отзыв согласия инвалидирует применимые старые черновики.

Сохранение плана и создание уведомления происходят одной транзакцией. Подготовка/предпросмотр не уведомляют. Отдельное подтверждение требуется для удаления аккаунта; внимание отправляется собственной кнопкой без дополнительного подтверждения.

### Search qualification

Первым проверить собственный серверный веб-поиск DeepSeek через Anthropic-совместимый интерфейс. Официальная интеграция Claude Code описывает его наличие, а Responses явно игнорирует встроенный web_search. Нужен контрактный тест прямого API: формат инструмента, источники и результаты, дополнительные расходы, возможность использования вне Claude Code и права на сохранение полей. Наличие функции в документации не считается проверенным качеством поиска мест.

До проверки используем адаптер SearchProvider с нормализованными результатами: title, source URLs, factual fields, retrieval date, unknowns, permitted media. Tavily и Brave — запасные кандидаты. Ни один не выбран автоматически. Подключение дорогого каталога требует согласования. Результаты веба — недоверенные данные, не инструкции. Яндекс Карты сохраняются как исходная ссылка, а при отсутствии точной ссылки даётся явно обозначенный поиск по названию/адресу, не выдуманный идентификатор организации.

Загрузчик пользовательских ссылок не обращается к loopback/private/link-local адресам, ограничивает redirects, размер и время, проверяя каждый redirect. Нельзя скрейпить и сохранять каталог в обход условий. API поиска не выдаёт права на любое найденное фото.

### Time and delivery

Хранить моменты планов в UTC и IANA timezone; относительные даты показывать явно, неоднозначные часы перехода времени уточнять. Feedback вычислять от календарной даты окончания в подтверждённом pair timezone; изменение timezone пересчитывает jobs, не plan instants.

SQLite outbox содержит semantic key (событие/версия/получатель), available_at, expires_at, статус, попытки и Telegram message_id. Quiet hours применяются перед отправкой и после сбоя. Плановые изменения в отложенной очереди объединяются. При блокировке бота не повторять заведомо постоянную ошибку; временные ошибки Telegram имеют ограниченный backoff в пределах актуальности. Это не автоматический повтор платных AI вызовов.

Telegram не даёт общей гарантии exactly-once: сбой после успешной отправки, но до фиксации результата может оставить неизвестный outcome. Отмечать uncertain и не создавать бесконечные повторы; дедупликация обеспечивает обычный путь и сохранённые callbacks, не обещает невозможного.

### Freeze computation

Автоматический freeze = последняя действительная точная дата посещения + 30 дней. Историческое посещение с приблизительной датой не создаёт точный deadline без выбора пользователя. Ручной override хранится отдельно, включая явное снятие, и не теряется при исправлении истории. Новый поход снова включает 30 дней: ручное снятие относится к предыдущему походу. Ручная будущая дата действует до истечения; после этого новый поход использует автоматический срок. Никогда не объединять «не были», отказ и freeze в одну колонку.

### Voice qualification and execution

Проверить multilingual Whisper tiny и base через whisper.cpp на CPU существующего VPS: RSS, время на коротком/длинном аудио, ошибки русских названий, даты и шум. Запуски последовательны как способ управления ресурсами, не квота пользователя: задачи стоят в очереди. Движок должен иметь ограничение времени/памяти и возможность остановки; бот продолжает обслуживать кнопки.

Выбрана tiny на текущем VPS; живую речь пользователь решил не проверять. Совместную нагрузку ядра проверяем синтетически. Каждая расшифровка подтверждается кнопкой «Верно» или исправляется до передачи ИИ. Второй сервер пока не нужен. Whisper не даёт надёжной пользовательской «уверенности» одной цифрой: проверки пустоты/повторов и сомнительных дат не гарантируют обнаружение всех ошибок.

### Conversation tone

Пользователь выбрал тёплую короткую подачу на «ты» с умеренными эмодзи. Карточки и подтверждения показывают конкретные факты и изменения; сообщения не навязывают романтическую болтовню.

### Privacy, dashboard and backups

Данные для модели собираются allowlist-ом после проверки согласия каждого; личный context никогда не включает переписку партнёра. Новая беседа меняет context boundary, очистка удаляет историю; retention-job удаляет сообщения старше 30 дней и просроченные временные drafts. Логи содержат метаданные и ошибки без токенов, raw prompts и аудио.

Панель только на 127.0.0.1:8080, локальная авторизованная сессия с секретом вне репозитория, CSRF для действий и проверка Origin. SSH-туннель не заменяет авторизацию панели. Ключи не отображаются. API usage хранит токены, тариф/валюту/дату, доступные search charges, оценочный курс и uncertainty; в прототипе денежные сигналы выключены (target=0).

Копия SQLite — через backup API в временный файл, integrity_check, atomic rename и ротация только после успеха. Daily+weekly managed slots ограничены четырьмя неделями; отдельный deletion ledger на том же VPS переживает восстановление старой БД. Не откатывать ledger вместе с DB; при отсутствии актуального ledger восстановление не открывается пользователям. Это защищает логическое восстановление, не потерю самого VPS.

## Risks / Trade-offs

- [Мало памяти и неизвестная CPU производительность] → нагрузочное измерение; ASR отдельно, если нужного запаса нет.
- [Поиск без гарантированных адресов/цен] → источник и unknown; никакого обещания соответствия непроверенному бюджету.
- [Поисковые лицензии и фото] → квалификация сохранения отдельно от стоимости и от ссылок на карты.
- [Никаких квот] → usage-метрики; бюджет отложен; расход не гарантирован сверху, опциональные будущие лимиты выключены.
- [Копии только на одном VPS] → корректная ротация и тест восстановления; потеря хоста уничтожает обе копии.
- [Старый прототип удаляет общие данные] → миграция до включения обработчиков нового релиза, не запускать прежнюю destructive логику рядом.

## Migration Plan

1. Провести qualification поиска и tiny/base; записать результаты, оставить ASR за пределами прототипа.
2. Создать новую версионируемую схему, миграцию существующих пар/карт/лайков, резервную копию и dry-run. Не переносить прежнее AI consent автоматически на расширенный состав данных.
3. Реализовать этапы tasks.md с проверками контракта; обязательные функции прототипа включить после их прохождения; не отмечать отложенные задачи выполненными.
4. Развернуть под отдельными service users без sudo, секреты вне checkout; проверить long polling, панель через туннель, расписание, ротацию и восстановление.
5. Для rollback остановить запись, сохранить текущее состояние и выбрать совместимую версию; необратимую схему не откатывать заменой файла поверх актуальных данных. Старый прототип не запускать на новой базе.

## Qualification status

Контракты поведения определены. Прототип не блокируется отложенным ASR; поиск DeepSeek проверен. Эти проверки имеют выделенные задачи; provisional adapters не являются выбором стороннего платного провайдера или одобрением покупки сервера.

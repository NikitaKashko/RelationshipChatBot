# Go-ядро

Go — выбранный язык первого релиза. Python в `app/` — исторический прототип, не production entrypoint. Полный релиз ещё реализуется; регистрационный polling доступен для разработки, на VPS пока не развёрнут.

Проверено с Go 1.27.2 на Windows. Зависимости закреплены в `go.mod` и `go.sum`: Telegram `github.com/go-telegram/bot`, SQLite `modernc.org/sqlite` без CGo. Бинарник для Linux amd64 собирается без Python и системного SQLite. Whisper.cpp останется отдельным процессом.

```powershell
go test ./...
go vet ./...
go run ./cmd/relationshipbot check
```

`check` читает локальный `.env` (переменные среды имеют приоритет), вызывает только Telegram getMe и выводит username без токена. Он не запускает polling и не изменяет webhook.

При отсутствии глобального Go в этом рабочем окружении доступен игнорируемый SDK `.tools/go-sdk/go/bin/go.exe`. Для него можно использовать локальные GOPATH/GOCACHE в `.tools/`; эти файлы не коммитятся.

```powershell
$env:GOOS='linux'
$env:GOARCH='amd64'
$env:GOAMD64='v1'
$env:CGO_ENABLED='0'
go build -buildvcs=false -trimpath -ldflags='-s -w' -o bin/relationshipbot-linux-amd64 ./cmd/relationshipbot
```

`GOAMD64=v1` подходит для VPS без AVX. `-buildvcs=false` позволяет собрать артефакт без Git metadata; версия приложения должна задаваться будущим release pipeline. Проверенная сборка ядра — около 11.1 MiB; это размер файла, не оценка памяти работающего бота.

## SQLite и переход с прототипа

Схема встроена в `internal/store/schema.sql`; `app/schema.sql` — копия для исторической Python-заготовки. Go использует `PRAGMA user_version=1`, WAL, foreign_keys, busy_timeout и короткие BEGIN IMMEDIATE транзакции. Один pooled connection задаёт явную сериализацию; сеть не выполняется внутри Write.

`go run ./cmd/relationshipbot migrate` открывает DATABASE_PATH, по умолчанию `data/release.sqlite`. Если в локальном `.env` уже указан другой путь, он имеет приоритет: перед реальной миграцией проверь путь. Тесты миграции используют только временные базы.

При открытии старой схемы создаётся неизменяемая recovery-копия `<база>.pre-v1.sqlite` через VACUUM INTO, затем в одной транзакции исходные таблицы переименовываются в legacy_* и переносятся симметричные пары, карты, категории и разрешённые лайки. Несимметричные связи не становятся парами; карты остаются личными. Старое согласие ИИ не переносится. Пользователи завершают профиль.

Повторное открытие не дублирует данные. Неизвестная/более новая схема отвергается. Recovery-копия не заменяет ежедневные бэкапы. Откат после новых записей требует отдельного плана: старый Python-бот нельзя запускать на новой схеме или возвращать snapshot поверх актуальных данных.

## Границы действий

Actor определяется Telegram update/авторизованной панелью, никогда аргументами модели. `UserFor`, `PairFor`, `PlaceFor`, `PlanFor` проверяют статус и scope. Прямой SQL в пользовательских обработчиках не должен обходить эти границы.

`actions.Prepare` строго декодирует allowlist аргументов и сохраняет черновик без изменения предметных данных. `Apply` проверяет автора, expiry и поколение пары; изменение и receipt записываются атомарно. Повторное подтверждение возвращает receipt без второй записи; принятие пары проверяет resulting pair, поскольку само меняет scope. После разрыва старый receipt недоступен.

`bootstrap` — явная локальная команда создания первого owner invite на семь дней, пока нет владельца. Она выводит bearer invitation; не публиковать его в публичных логах. Обычные access invitations может создавать только владелец, partner invitations — зарегистрированный пользователь без пары. Хранятся SHA256-хеши случайных токенов. Claim сериализован, закрепляется за первым аккаунтом и продолжается после перезапуска.

Реализована основа и три действия: профиль, согласие, подтверждение пары. Telegram-интерфейс поддерживает /start с приглашением, продолжение города/имени/часового пояса после перезапуска, preview и сохранение профиля, /invite и подтверждение пары. Голосовые, остальные действия, планировщик, ИИ и панель ещё не подключены; наличие таблиц не означает готовность функций.

Для разработки можно создать пустую базу командой `bootstrap`, открыть бота с выданным /start payload и запустить `serve`. Это регистрационная версия, не приёмка полного релиза. Один токен обслуживается одним polling-процессом. Состояние регистрации хранится в SQLite drafts; не копируйте приглашения в публичные логи.

# Runtime-тексты и объявления

Пользовательский контент лежит отдельно от Go-кода:

- `content/ru.json` — сообщения бота, подписи кнопок, карточки, уведомления и промпты;
- `content/panel.html` — HTML и формулировки панели владельца;
- `content/announcement.json` — короткое объявление текущего функционального релиза.

Бот читает файлы при запуске. Для изменения текста не нужна пересборка: найди текущую фразу в `ru.json`, измени только значение справа от ключа, проверь каталог и перезапусти сервис. Не удаляй ключи и не меняй набор `%s`, `%d`, `%f` в строках: валидатор считает их обязательными параметрами.

```bash
sudo -u relationshipbot /opt/relationshipbot/relationshipbot check-content
sudo systemctl restart relationshipbot-bot
```

Для панели измени `panel.html`, затем перезапусти `relationshipbot-panel`. Рабочие файлы на VPS находятся в `/opt/relationshipbot/content`. Перед правкой сохрани копию файла; если новый файл повреждён, сервис не должен успешно стартовать — верни копию и повтори restart.

## Объявление обновления

`announcement.json` содержит:

- `enabled` — ставить ли сообщение в очередь;
- `id` — уникальный идентификатор релиза;
- `text` — коротко, что изменилось и как этим пользоваться.

При старте основного бота сообщение один раз ставится в долговечную очередь каждому пользователю со статусом `ready`. Обычные тихие часы действуют. Повторные рестарты с тем же `id` не создают дублей. Для следующего функционального обновления измени одновременно `id` и `text`. Если уведомление не нужно, установи `enabled: false`.

Проверить конкретную фразу можно тем же бинарником без запуска Telegram polling:

```bash
/opt/relationshipbot/relationshipbot check-content internal.telegram.menu.001
```

Это печатает значение выбранного ключа. Секретов в каталоге быть не должно.

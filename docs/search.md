# Поиск и распознавание мест

Реализовано в Go через собственный серверный Web Search DeepSeek, отдельный поисковый ключ не требуется. Обновлённый поток развёрнут в изолированном тестовом боте; основной бот обновляется после пользовательской приёмки.

## Как пользоваться

- «Найди новые кафе в центре Москвы» — поиск новых идей.
- «Поищи в интернете концерт на выходные» — явный интернет-поиск.
- Публичная HTTPS-ссылка на место — распознавание и заполнение карточки. Работает также `/add ссылка`.
- «Хочу добавить кафе Ладо на Кривоколенном» — ИИ распознаёт конкретное место и предлагает заполненную карточку.
- `/search название или описание` — явный поиск без предварительного вызова модели-маршрутизатора.
- `/add название | категория | адрес | карта` — ручная альтернатива без ИИ.

«Куда сходить вечером?» по умолчанию использует коллекцию. Одно согласие пользователя на ИИ покрывает его последующие поиски; отдельной кнопки разрешения на каждый запрос нет. Явная просьба найти места в интернете, публичная ссылка или конкретное место запускают поиск сразу и показывают статус. Отрицания вроде «без интернета» учитываются отдельно. Город пары используется как ориентир; город поездки в запросе имеет приоритет и не изменяет профиль. При отсутствии нужного города бот уточняет его. Для личного поиска достаточно согласия автора, а чтение общей коллекции через ИИ по-прежнему требует согласия обоих.

## Карточка и подтверждение

При достаточных источниках выдача содержит до пяти отдельных карточек. Если поддержано меньше — показывается меньше, без дополнения из памяти модели. Для неоднозначного описания возможны до трёх вариантов/филиалов с уточнением. Каждая карточка содержит только подтверждённые доступные поля: название, категории, адрес, краткое описание, цену и источники. Неизвестные строки не выводятся. Приоритет отдаётся точной ссылке Яндекс Карт; если её нет в источниках, кнопка открывает явно подписанный поиск Яндекса по названию и адресу. Telegram запрашивает preview этой ссылки, но внешние фотографии не копируются.

У каждой карточки своя кнопка «➕ Добавить в коллекцию». Ничего не записывается до её нажатия. После сохранения бот явно пишет «Добавлено в коллекцию», показывает автоматическую оценку автора «хочешь сходить» и оставляет действие добавления в черновик свидания. Повторная оценка и немедленный архив в этом подтверждении не показываются; они доступны при обычном открытии карточки из коллекции. Неизвестные адрес, бюджет и часы в сохранённой карточке не печатаются. Повтор того же callback возвращает прежний результат. Чужая кнопка и черновик после отзыва согласия недоступны. Если карточка уже сохранена, бот предлагает существующую, сохраняя автора; дубль молча не создаётся. При создании пары личные коллекции обоих объединяются в одну общую с сохранением авторов.

Когда найденное совпадает с существующей карточкой, показывается она. Фриз/отказ/архив не обходятся новым ID при автоматическом поиске; явное распознавание ссылки позволяет увидеть такое место для ручного выбора. Точная ссылка на Яндекс Карты допускается только из результатов поиска. Иначе кнопка-навигация — явно подписанный поиск по названию/адресу, без придуманного ID организации.

Источники должны буквально присутствовать в `web_search_tool_result`; ссылки, придуманные моделью, не принимаются. Для заполненных фактических полей требуется ссылка из источников соответствующей карточки. Это проверка происхождения ссылки, а не независимая гарантия истинности каждого факта: карточка помечена как подготовленная ИИ, сохранение требует проверки человеком. Актуальность необходимо сверять у заведения.

## Ошибки и расходы

Нативный поиск выполняется один раз за запрос; повторный tool call в том же запросе использует результат, повтор после ошибки — только кнопкой. «Ещё варианты» — отдельный одноразовый запрос, который можно отправить снова новой кнопкой. Сетевые ошибки/неполный JSON сохраняют запрос и usage, если он доступен. Тихих платных повторов нет.

В `api_usage` поиск выделен как `deepseek_search`, сохраняются видимые входные/кешированные/выходные токены, оценка стоимости и число попыток инструмента. `search_requests` не равен числу успешных поисков. У DeepSeek поиск может вызывать дополнительные summarization calls; их полное включение в возвращаемый usage не подтверждено, поэтому поисковая сумма всегда помечена `uncertain`. Отсутствующий usage — неизвестная сумма, не ноль. Рублёвая оценка и цель 500 ₽ используют общую конфигурацию; остановки запросов нет.

## Воспроизводимая проверка

После сборки CLI и настройки локального `.env`:

```powershell
.\bin\relationshipbot-check.exe check-search
.\bin\relationshipbot-check.exe check-search 'Найди место по этой ссылке: https://mm-g.ru/articles/gurman-puteshestviya/avero-mio-bistro/'
```

Команды платные, запускаются явно; в CI используются fake providers. Ключ не выводится, личная база не открывается, encrypted search content не сохраняется и не печатается. Контракт POST `/anthropic/v1/messages`: `model=deepseek-flash`, `thinking=disabled`, `max_tokens=3500`, инструмент `{type:web_search_20250305,name:web_search,max_uses:3}`. Три использования — ограничение одного вызова от циклов модели, не пользовательская дневная/месячная квота.

12.10.2026: общий запрос дал две карточки с источниками, usage 16638 input (включая 1024 cached)/1396 output, две попытки web search. По публичной ссылке найдено Avero Mio Bistro, адрес «ул. Петровка, 34, стр. 1», три источника; 13794 input (1024 cached)/754 output, две попытки. Адрес соответствует опубликованной [странице источника](https://mm-g.ru/articles/gurman-puteshestviya/avero-mio-bistro/). Другой результат общего запроса независимо не подтверждён; поиск не заменяет каталог заведений. Первый прогон обнаружил текстовую преамбулу перед финальным JSON; исправлен разбор отдельного финального блока, покрыт тестом.

## Квалификация поставщика

Прямой серверный поиск доступен вне Claude Code, подтверждён живыми запросами. [Официальная документация](https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/) описывает дополнительный расход токенов; [Anthropic-совместимость](https://api-docs.deepseek.com/guides/anthropic_api/) — серверные блоки поиска. На основании проверки используем этот адаптер для первой версии; Tavily/Brave остаются заменяемыми кандидатами, их ключи/платные планы не подключены.

[Условия API DeepSeek](https://cdn.deepseek.com/policies/en-US/deepseek-open-platform-terms-of-service.html), разделы 4.1–4.2 и 8.1, допускают использование output при соблюдении прав третьих лиц и требуют обозначать ИИ-происхождение. Это не лицензия на фотографии или копирование страниц. Здесь сохраняются краткие самостоятельно сформированные карточки фактов и ссылки по подтверждению пользователя, без полных материалов, отзывов и изображений сайтов. Условия источника продолжают действовать; для массового каталога потребовалась бы отдельная квалификация.

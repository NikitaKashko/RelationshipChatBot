# ИИ и знаки внимания (Go)

Этап разработки, полный релиз пока не развёрнут. Основной интерфейс — обычные текстовые сообщения; команды и кнопки остаются доступными. Интернет-поиск, ASR, полный учёт денежных расходов и панель ещё впереди.

## Внимание

В `/start` пары и `/attention` — «Хочу внимания», «Думаю о тебе», «Хочу обнять». Нажатие сразу ставит сообщение в очередь, без ввода текста, дополнительного подтверждения и платного ИИ. Для каждой кнопки шесть готовых фраз; предыдущая фраза этой кнопки не повторяется. Один знак на отправителя в минуту **между всеми тремя кнопками**, включая конкурентные нажатия. Получатель соблюдает личные тихие часы; сообщение истекает через 12 часов.

`/names Никита | зайка` → подтверждение: слева своё имя отправителя, справа своё обращение к партнёру. Получательское обращение имеет приоритет перед именем отправителя. Чтобы убрать замену, оставить справа пусто: `/names Никита |`. Чужие настройки не меняются.

## Согласие и диалог

Оба партнёра включают `/ai` с явным подтверждением передачи данных. До этого запросы общей коллекции не отправляются провайдеру. `/ai_off` выключает личное согласие и инвалидирует неприменённые ИИ-черновики пары; повторное включение не возрождает их. Обычные ручные действия работают без согласия. Согласие проверяется перед каждой API-итерацией, после ответа и при сохранении ИИ-черновика.

Можно написать:

- «Куда сходить вечером?»
- «А подешевле и без кино?»
- «Подготовь свидание завтра с 18 до 20, из нашей коллекции»
- «Перенеси план на пятницу»
- «Измени название места …»
- «Прошлый поход понравился, но пока не хочется повторять»

ИИ читает свежие данные через ограниченные функции, уточняет недостающие сведения и создаёт черновик. Предпросмотр показывает точные календарные даты и время, включая относительное «завтра». Только «Сохранить» меняет данные и ставит событие партнёру в очередь. Текстовый разбор отзыва предлагает личную оценку/желание вернуться/комментарий и сохраняется той же кнопкой. Удаление аккаунта, завершение пары, приглашения и внимание исключены из ИИ-инструментов.

`/newchat` начинает новый личный контекст, сохраняя историю до её истечения; `/clearchat` удаляет всю личную историю и прежние retry-кнопки. Сохранённые места, планы и подтверждённые предпочтения остаются. Контекст не смешивается с перепиской партнёра и прежней пары. Сообщения удаляются через 30 дней, при запросе/старте и ежечасной уборке; очистка действует и при выключенном провайдере. После остановки приложения уборка выполняется при следующем старте. Для API берётся ограниченное окно истории, сама история хранится по полному 30-дневному правилу.

## Данные и границы

Разрешены нужные поля места (внутренний ID карточки, название, категории, город, адрес, цена с основанием, интерес), даты/версии планов, посещения, общие кнопочные оценки и подтверждённые структурированные предпочтения. Telegram ID, имена для уведомлений, фото, тексты чужой переписки, сохранённые заметки и комментарии отзывов в этот адаптер не передаются. Тексты заметок/сохранённых отзывов даже при будущих разрешениях остаются исключёнными на этом этапе. Текущий добровольно присланный текст автора обрабатывается как его собственный запрос.

Чтение выдачи исключает archived/frozen/refused до ранжирования, приоритет совпадений и неизвестный интерес партнёра различаются. Явный бюджет проверяется по цене карточки с пересчётом «на человека/двоих»; неизвестная цена возвращается отдельной группой. Полный контроль суммарного бюджета маршрута и всех уточняемых условий ещё относится к незавершённой задаче 7.3.

Инструменты принимают закрытые структуры без user_id/pair_id и не исполняют произвольный SQL/shell/HTTP. Недоверенные названия и источники не дают разрешений. При текстовой правке отсутствующие поля карточки сохраняются; фото/источники берутся из БД и не придумываются моделью. Предпросмотр для человека не отражается в API или истории: сохранённые приватные поля не утекут через него. ИИ-план до сохранения доступен в личном контексте как структурированный черновик без скрытых полей.

Пользовательские сообщения не требуют команд. Интернет-инструмента в этом этапе нет: бот должен явно сообщать о недоступности поиска, без выдачи локальной коллекции за найденные в интернете места.

## Ошибки и проверка

Ошибка провайдера сохраняет запрос и уже подготовленные черновики, даёт приватную одноразовую кнопку «Повторить». Автоматического повторения платного неуспешного вызова нет. Последовательные tool calls — части нормального запроса; восемь раундов ограничивают зацикливание модели, а не число пользовательских запросов. Запросы одного пользователя обрабатываются последовательно для порядка контекста. Месячных/дневных ИИ-квот и остановки по бюджету нет.

Каждая API-попытка пишет usage, отдельно учитывая кешированные входные токены. Для известных моделей сохраняется оценка в USD по пиковым тарифам — консервативно, без календаря китайских праздников. Тарифный снимок проверен 11.10.2026 по [официальной таблице](https://api-docs.deepseek.com/quick_start/pricing/); при изменении цен его нужно обновить. Это оценка, не счёт провайдера. Отсутствующий/некорректный usage и неизвестный тариф не считаются нулевым расходом. Учёт результата выполняется и после отмены исходного запроса.

`BILLING_USD_RUB` задаёт бухгалтерский курс для новых запросов; значение `0` по умолчанию означает, что рублёвая оценка неизвестна. Курс не запрашивается автоматически и старые записи не пересчитываются. При заданном курсе `BILLING_TARGET_RUB=500` ставит одно уведомление владельцу за календарный месяц UTC, с обычными тихими часами и сроком актуальности семь дней. Достижение цели не останавливает запросы; неизвестные расходы отмечаются отдельно. Значение цели `0` отключает сигнал. Перед развёртыванием требуется задать курс. Учёт будущего поискового провайдера и конфигурация будущих квот ещё не завершены, поэтому задача 7.6 пока открыта.

API: [официальный Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/), `thinking=disabled`, ограниченный HTTP timeout, без redirect и логирования сырых ошибок. `check-ai` — платный синтетический smoke одного ответа; `check-ai-flow` — платная синтетическая временная база для tool flow, без реальных пользователей и записей production. Запускать явно, не добавлять в автоматический CI.

11.10.2026 `check-ai-flow` прошёл: три API-вызова, ровно подготовленный черновик на 12.10.2026, реальных/подтверждённых планов ноль. До успешного прогона убрано лишнее уточнение маршрута с одним местом. Unit/integration-тесты используют fake provider и проверяют privacy, consent/withdrawal, историю, уточнения, кнопки, фриз, бюджет на карточку, ошибки/usage и отсутствие неподтверждённых записей.

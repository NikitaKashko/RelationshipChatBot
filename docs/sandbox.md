# Изолированный тестовый бот

Создай **второго** бота через @BotFather → `/newbot`. В локальном `.env`:

```dotenv
TEST_BOT_TOKEN=токен_второго_бота
TEST_OWNER_ID=твой_числовой_Telegram_ID
TEST_DATABASE_PATH=data/sandbox.sqlite
```

ID владельца уже зарегистрированного основного бота можно получить командой `go run ./cmd/relationshipbot owner-id`. Эта команда печатает только ID. Токены не отправляй в чат и не сохраняй в Git.

Проверка токена: `go run ./cmd/relationshipbot check-test`; она не отправляет сообщения и проверяет, что бот отличается от основного. Запуск: `go run ./cmd/relationshipbot serve-test`. Затем открой **тестового** бота и отправь `/start`. Основной бот может работать параллельно. Тестовая команда требует отдельного токена и базы с именем `sandbox.sqlite`; повторный запуск сохраняет тестовые данные. Непустая база без маркера тестового режима и база другого владельца отклоняются. На VPS тестовая служба имеет отдельного системного пользователя, секреты и бинарник `/opt/relationshipbot/relationshipbot-test` без доступа к production-базе; пример unit — `deploy/relationship-test.service`. Это позволяет проверять изменения без замены бинарника и рестарта основного бота.

Кнопки «🧪 Роль А» и «🧪 Роль Б» переключают виртуального участника; запасные команды `/role_a`, `/role_b`. Роль А — тестовый владелец, Б — партнёр. Новая база уже содержит пару с городом Санкт-Петербург и часовым поясом Europe/Moscow. Сообщения обеих ролей приходят тебе с пометками. Кнопки старых сообщений сохраняют исходную роль и переключают текущую на неё. Отправка реальным посторонним получателям запрещена, чужие аккаунты и группы не обрабатываются.

## Проверка подписи внимания

1. Роль А → «Внимание» → «Думаю о тебе». Уведомление роли Б содержит имя профиля твоего Telegram.
2. Роль Б → «Настройки» → «Имя партнёра в уведомлениях» → «Задать имя партнёра» → `зайка` → сохранить.
3. Через минуту роль А отправляет «Хочу обнять». Роль Б получает уведомление с `зайка`.
4. Роль Б сбрасывает обращение через «Имя из Telegram». Следующий знак снова подписан именем профиля.
5. Отправь знак от Б к А: обращение, выбранное Б, на сообщения для А не влияет. Тихие часы и минутная задержка работают по обычным правилам: внимание игнорирует тихие часы, остальные уведомления учитывают их.

Для проверки ИИ включай помощника отдельно у каждой роли: ни у кого / только А / только Б / у обоих. Согласие каждой роли даётся один раз и покрывает её дальнейшие запросы и явный интернет-поиск. Ручное добавление и общие черновики доступны всегда; подбор из общей базы требует обоих согласий. Не сохраняй в тестовом диалоге чужие реальные личные данные. DeepSeek работает через настоящий API с обычными расходами.

Тест не заменяет проверку Telegram-доставки на два физических аккаунта. Автоматическое восстановление начальной пары после её удаления не выполняется; для полного сброса останови тестовую службу и замени только её отдельную базу новой пустой директорией. Основную базу не трогай.

# База первого релиза

Обновление: пользователь выбрал Go. Актуальная реализация и миграция — `internal/store`, действия — `internal/actions`; см. [go-development.md](go-development.md). Описание ниже сохранено как документация Python-заготовки, её не продолжаем как production-ядро.

`app.storage.Database` — новая версионируемая SQLite-база; `app.db.Store` и прежний `app.bot` пока остаются прототипом. До переключения Telegram entrypoint новую базу не открывать старым ботом.

Первое открытие прототипной базы автоматически создаёт неизменяемую recovery-копию `<имя>.pre-v1.sqlite`, затем в одной транзакции переименовывает исходные таблицы в `legacy_*`, создаёт новую схему и переносит пользователей, подтверждённые симметричные пары, места, категории и лайки. Разорванные/неполные старые связи не становятся активной парой; собственные карты сохраняются лично. Исходные таблицы остаются для аудита миграции. Ранее удалённые самим прототипом данные восстановить невозможно.

AI consent не переносится: новая интеграция передаёт расширенный состав данных. Мигрированные пользователи завершают профиль городом и часовым поясом. Старые заявки пары не продлеваются.

Идемпотентность миграции определяется `PRAGMA user_version`; более новая/неизвестная схема отвергается. Откат: остановить приложение, сохранить актуальную базу вместе с WAL, восстановить recovery-копию только при отсутствии новых записей или после отдельного плана обратной миграции. Старый код не совместим с новой схемой. Runtime backup/deletion restore реализуются отдельным этапом, recovery-копия миграции их не заменяет.

Действия получают actor ID из Telegram update или авторизованной панели. ИИ не задаёт actor/pair scope. `Database.place/plan/require_pair` проверяют текущую активную пару или личный scope; SQL-обход этих методов в пользовательских обработчиках недопустим.

`IdentityService` хранит только хеши приглашений, сериализует принятие пары и поддерживает незавершённую регистрацию. Начальный owner invite выдаётся локально; обычные access invite — только owner. Подтверждение предложенного города — второй участник, по актуальной версии. `Actions.prepare` сохраняет черновик; `Actions.apply` проверяет автора, срок, текущую пару и атомарно выполняет действие. Повторное подтверждение не выполняет запись снова.

Проверка: `.venv/Scripts/python.exe -m unittest discover -s tests -v`. Тесты используют временные базы и fake clock, без Telegram и API-ключей.

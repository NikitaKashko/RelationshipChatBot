# RelationshipChatBot 💛

Приватный Telegram-бот для пары: общая копилка мест, планы свиданий и знаки внимания. Текущая версия — прототип на **Go + SQLite**, с DeepSeek и лёгкой панелью владельца. Python-код в репозитории — исторический прототип, на сервере он не используется.

## Что уже работает

- **Крупные кнопки вместо набора команд:** постоянное меню Telegram для копилки, свиданий, помощника, внимания, приглашения и настроек. Включённый помощник показывает сохранённое состояние; повторное открытие не просит согласие заново. Команды остаются запасным способом.

- **Вход только по ссылке.** Владелец создаёт одноразовые приглашения доступа в панели. Пользователь без пары получает ссылку для партнёра через `/invite`: партнёр регистрируется и сам подтверждает создание пары. Код дружбы убран. Ссылки действуют 7 дней, закрепляются за первым Telegram-аккаунтом; регистрацию можно продолжить через `/start`.
- Личный город, имя для уведомлений и часовой пояс при регистрации. Город и часовой пояс пары предлагает один, подтверждает второй.
- **Копилка идей:** несколько категорий, добровольные оценки, фильтры, дубли, архив и фотографии пользователя. Карточки содержат адрес, источник и ссылку на Яндекс Карты, если данные доступны. Интернет-фото автоматически не копируются.
- Общие кандидаты для ближайшего свидания и несколько сохранённых планов. Точные дата, начало, конец и порядок мест проверяются перед сохранением. Об изменениях плана партнёру приходит уведомление; конфликт версий не затирает чужую правку.
- **ИИ как основной интерфейс:** обычный текст, личный контекст и уточнения. Изменения становятся черновиком и сохраняются кнопкой. Для использования данных пары оба включают `/ai`; переписка каждого остаётся личной и хранится 30 дней.
- По умолчанию ИИ выбирает из вашей копилки. Интернет-поиск DeepSeek включается по явной просьбе. Ссылку на место можно просто отправить боту: он ищет сведения и предлагает заполненную карточку с кнопками добавления. Неоднозначные описания требуют уточнения. Непроверенные сведения отмечаются, результаты сами не сохраняются.
- **«Хочу внимания», «Думаю о тебе», «Хочу обнять»** — одним нажатием, с разными готовыми фразами и вашим обращением. Один знак в минуту, без платного вызова ИИ.
- Посещения и личные отзывы, общий фриз на 30 дней. Замороженные места и личный отказ исключены из автоматического подбора; вручную выбирать можно. «Не пошли» не создаёт посещение и фриз.
- Долговечная очередь уведомлений: тихие часы 23:00–09:00, напоминание за 2 часа, опрос обоим в 12:00 на следующий день после окончания свидания. Без повторных опросов при молчании. Полной гарантии exactly-once Telegram не даёт; неопределённые доставки отдельно отмечаются.
- **Панель владельца:** графики запросов и токенов, ошибки, очередь, общие счётчики, приглашения доступа, ручной бэкап и его результат. Только `127.0.0.1:8080`, SSH-туннель, пароль, часовая сессия, CSRF и проверка Origin. Без переписки, текстов отзывов и API-ключей.
- **Бэкапы:** ежедневно, 7 дневных и 4 недельных копии на том же VPS, не старше 28 дней. Согласованный снимок SQLite, integrity/foreign-key check, проверка места на диске, ротация после успешного копирования.

## Как попробовать

1. Открой свою ссылку приглашения и заверши профиль: город → имя → часовой пояс → сохранение. Для Москвы/Санкт-Петербурга есть кнопка «Московское время»; также понимает «Москва», `Moscow` и `Europe/Moscow`.
2. Отправь партнёру ссылку из `/invite`. После его регистрации и подтверждения пары задай `/location`, второй подтвердит через `/start`.
3. Оба включите `/ai` и подтвердите согласие.
4. Напиши «добавь идею: пикник у озера», отправь ссылку на заведение или попроси «найди новые кафе в Москве». Сохрани понравившиеся карточки.
5. Напиши «подготовь свидание завтра с 18 до 21 из нашей копилки». Проверь даты и нажми «Сохранить».
6. Попробуй знаки внимания, `/places`, `/plans` и отзывы после свидания.

Команды запасного ручного интерфейса и формы: [коллекция и планы](docs/collection-and-plans.md), [посещения и отзывы](docs/visits-and-notifications.md). `/cancelinvite` отменяет твои действующие приглашения партнёра; `/invite` выпускает новые. `/newchat` начинает новый контекст, `/clearchat` очищает переписку, `/ai_off` отзывает согласие.

## Что отложено

Голосовые, расчёт бюджета свидания, денежные графики/уведомление 500 ₽ и квоты — вне текущего выпуска. Расходы внешнего API продолжают списываться провайдером; счётчики usage сохраняются. При нехватке подтверждённых результатов поиск может показать меньше 3–5 карточек.

Следующие итерации: завершение пары с личным архивом, экспорт/удаление аккаунта и независимый replay удалений при восстановлении, расширенные настройки уведомлений и дальнейшее улучшение разговорных сценариев. Эти действия пока не представлены как готовые функции. Прототип рассчитан на небольшой закрытый тест; регистрация по приглашениям не включает полноценную модерацию для публичного запуска.

## Локальный запуск

Нужен Go 1.26+ (проверено на 1.27.2). Скопируй `.env.example` в `.env`, добавь токен BotFather и ключ DeepSeek. Секреты и базу не коммить.

```sh
go test ./...
go vet ./...
go run ./cmd/relationshipbot migrate
go run ./cmd/relationshipbot check
go run ./cmd/relationshipbot bootstrap
go run ./cmd/relationshipbot serve
```

`bootstrap` выдаёт одноразовый `/start TOKEN` для первого владельца. Открой `https://t.me/<bot_username>?start=TOKEN`. После создания владельца повторный bootstrap запрещён. Для панели задай случайный `PANEL_PASSWORD` длиной минимум 24 символа и в отдельном терминале запусти:

```sh
go run ./cmd/relationshipbot panel
go run ./cmd/relationshipbot backup
go run ./cmd/relationshipbot verify-backup /absolute/path/to/snapshot.sqlite
```

Не запускай одновременно две polling-копии одного бота. `BILLING_TARGET_RUB=0` отключает прежние денежные уведомления. Панель рассчитана на адрес `http://127.0.0.1:8080` или `http://localhost:8080`.

## Развёртывание и восстановление

Go-бинарник без CGO, SQLite WAL и systemd, без Docker/Redis/PostgreSQL. [deploy/prototype-setup.sh](deploy/prototype-setup.sh) устанавливает два процесса одного бинарника под отдельными служебными пользователями без sudo и ежедневный backup timer в 03:10 UTC. Секретные environment-файлы находятся вне checkout. Адрес сервера, ключи и персональные команды доступа сохранены только локально у владельца.

Панель открывается через локальный SSH-туннель к loopback-порту 8080. Снаружи открыт только SSH. Локальные резервные копии не защищают от потери самого VPS.

Для восстановления: остановить бот и панель, сохранить текущую БД вместе с WAL/SHM как отдельный набор, проверить выбранный snapshot командой `verify-backup`, перенести **копию** проверенного snapshot в новый путь, выставить права общей служебной группы и переключить оба процесса на этот путь. Старый файл и его WAL/SHM не смешивать со snapshot. Сначала проверить миграцию и запуск, затем возобновить доступ. Snapshot с непустым deletion ledger отвергается до появления независимого механизма повторного удаления; удаление аккаунта в прототипе недоступно.

План и будущие требования: [OpenSpec](openspec/changes/plan-date-lifecycle/). Незавершённые пункты честно остаются в списке задач.
